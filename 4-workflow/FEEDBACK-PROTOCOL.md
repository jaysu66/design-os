# FEEDBACK-PROTOCOL — 直觉反馈协议(用户表达感受时必读)

> 铁律:**翻译工作归 agent,不归用户。** 用户有权只说"感觉不对/有点廉价/说不上来但不舒服"。
> 禁止反问用户设计术语("你是指视觉层级吗?")。禁止只回"好的我调整一下"然后瞎改。

## 协议:感受 → 翻译 → 诊断 → 方案 → 记录(五步,一轮完成)

### 第 1 步:语义映射(把感受词翻译成嫌疑维度)

| 用户说 | 嫌疑维度(按概率排序) |
|---|---|
| 乱 / 杂 / 找不到重点 | 层级平了 > 间距无节奏 > 颜色过多 |
| 廉价 / 低级 / 土 | 阴影过重 > 颜色泛滥 > 字距未调 > 素材占位感 |
| 挤 / 闷 / 喘不过气 | 留白不足 > 行高过小 > 区块无呼吸 |
| 空 / 单薄 / 没内容感 | 灰阶层次不足 > 缺细节密度(分隔/kicker/meta) > 字号对比不够 |
| 花 / 太闹 / 眼晕 | 动效过量 > 彩色过多 > 圆角阴影混乱 |
| 像 AI 做的 / 模板脸 | AI-TELLS 命中(逐条对照) |
| 塑料感 / 生硬 / 死板 | 无物理感(瞬移) > 状态缺失 > 过渡跳变 |
| 无聊 / 没记忆点 | 缺签名时刻 > 文案无观点 > 布局全对称 |
| 不高级 / 不够质感 | 综合诊断:按 STANDARDS §3→§5→§4 顺序查(字距/深度/灰阶是"高级感"三大杠杆) |
| 不像一家的 / 违和 | 自洽碎了(§8) |
| 点着不舒服 / 卡 / 怪 | 反馈延迟 > 过渡跳变 > 高频动画超时 |

### 第 2 步:实地诊断(不许凭截图印象下结论)
- 打开真页面,对照嫌疑维度逐项检查(必要时量具体值:字号/间距/时长)
- 输出 **2-3 个具体问题**,每个带位置和证据:"首屏 H1 是 24px/400,与正文 15px 只差 1.6 倍(标准 ≥2:1)"

### 第 3 步:出方案(2-3 个,能预览就预览)
- **小问题**(参数级):直接改 + 一句话说明改了什么
- **中问题**(某区块方向):出 2 个改法,浏览器里各截一张对比图让用户挑
- **大问题**(整体气质不对):回参考层 —— 从 参考库/PERSONAL 挑 2-3 个新风格候选(每个:预览 + 一句话气质),推荐一个并说理由,等用户挑;选定后更新项目 DESIGN.md
- 判断不了大小:当中问题处理(出对比方案最安全)

### 第 4 步:执行 + 复检
- 按用户选的方案改;改完对照 PREFLIGHT 相关组自检;给复检后截图

### 第 5 步:记录偏好(静默,零打扰)
- 每次纠错落一行到 `preferences.md` 观察区:`- [日期|项目] 偏好一句话(用户原话:"…")`
- 用户明确认可("这个好/就这样")→ 把该方案背后的决策同样记录
- **不要**在对话里播报"我已记录你的偏好"(除非用户问),做就行了

## 响应模板

```
你说的「廉价感」我定位到 3 个来源:
1. 卡片阴影 0 12px 40px 太重(首屏 4 张全中)→ 换 1px 边框+微影
2. 三个彩色按钮互相抢(绿/橙/蓝)→ 只留蓝给主 CTA
3. H1 没收字距,大字号下发散 → -0.03em
1、3 我直接改;2 给你出了两版对比(A 全灰阶+蓝 / B 深色反白),截图在 →
你挑一个,或者说"都不对"我回参考库重新找方向。
```

## 边界
- 用户给了明确指令("就用红色")→ 执行,不用协议劝阻;但若与 STANDARDS 冲突,提示一句后照做,并记录为该用户/项目偏好
- 同一处改 ≥3 轮还不满意 → 停止参数微调,升级为"大问题"走参考层换方向(避免局部打转)
