# WORKFLOW — 系统总流程(5 个入口 + 治理)

> agent 视角的操作手册。用户视角见 5-human/使用手册.md(内容同源,口径一致)。

## 入口①:新项目起步(触发:"用 design-os 起步 / 做个 XX 网站/应用")

```
1 收 brief:表达什么 / 给谁看 / 参考(可无)/ 绝对不要(可无)
   —— 用户没给全就用一次追问补齐,别连环问
2 找参考(读 3-references/ENGINE.md):
   PERSONAL 有匹配 → 优先;否则从参考库按气质检索;用户丢了链接 → 走 EXTRACT 提取
3 出 3 候选:每个 = 名字 + 一句话气质 + 预览(截图或 tokens 摘要),推荐 1 个并给理由 → 停,等用户挑
4 写项目 DESIGN.md(按 DESIGN-TEMPLATE,一页,含"本项目绝不"清单)→ 停,等用户点头
5 实现:带着 1-judgment 全套 + 项目 DESIGN.md;技法查 2-techniques
6 自检:PREFLIGHT 全组跑完,先自己修一轮
7 交付:真页面 + 三档截图 + 自检报告 → 进入反馈循环(FEEDBACK-PROTOCOL)
```

## 入口②:日常 UI 任务(触发:任何涉及界面的实现/修改,用户无需说任何暗号)

```
1 读项目 DESIGN.md(没有 → 轻量补一份,或问用户要不要走入口①)
2 读 preferences.md 总偏好区
3 实现 → PREFLIGHT 相关组自检 → 交付
```

## 入口③:收藏(触发:"这个网站不错 / 存进设计库 / 学一下这个风格" + 链接)

```
走 3-references/EXTRACT.md 协议 → 产出 PERSONAL/<站名>-<日期>/DESIGN.md + 截图
→ 回一句:已入库,提炼出的气质是 XX(一句话),下个项目可直接引用
```

## 入口④:直觉反馈(触发:用户对现有 UI 表达任何感受)

```
走 FEEDBACK-PROTOCOL 五步:翻译 → 诊断 → 方案 → 执行 → 静默记录偏好
```

## 入口⑤:复盘治理(触发:"design-os 复盘",或一个项目收尾时 agent 主动提议)

```
1 读 preferences.md 全文
2 整合:
   - 观察区条目在 ≥2 个项目出现过同类 → 合并措辞,移入总偏好区
   - 总偏好区互相矛盾 → 列给用户裁决(唯一需要用户出场的环节)
   - 90 天未再触发 → 移入休眠区(不删)
3 项目层:把该项目 design 相关经验一句话写进项目 DESIGN.md 附注
4 git commit(本目录),commit message 概括"这轮学到了什么"
5 给用户 5 行以内小结:新转正偏好 / 休眠数 / 需裁决项
```

## 治理规则(防腐烂)

- **体积上限**:STANDARDS / AI-TELLS 各一页;preferences 总偏好区 ≤30 条 —— 满了必须先合并淘汰再进新
- **转正门槛**:跨项目 ≥2 次才进总偏好;单次纠错永远只进观察区
- **风格隔离**:总偏好只收"风格无关"的条目(判据:暗色工具站和浅色杂志站是否都成立);风格取向只进具体项目 DESIGN.md
- **例外优先**:用户当场指令 > 项目 DESIGN.md > preferences > STANDARDS;冲突时执行高优先级并记录该例外
- **一切留痕**:本目录 git 管理,用户随时 `git log/diff` 看"系统学习史"
