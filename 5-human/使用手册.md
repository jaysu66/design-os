# design-os 使用手册(给人看的那份)

> 这套系统里,agent 是设计师,**你是创意总监**。
> 总监不需要会做设计,只需要两样本事:**看得出哪里不对,说得出哪里不对。**
> 看的训练 → 打开 [审美训练.html](审美训练.html);说的模板 → [沟通速查.md](沟通速查.md)。

## 系统一图

```
design-os/
├── 1-judgment/    agent 的判别力:什么是好、AI 味禁令、出厂自检清单
├── 2-techniques/  agent 的手艺:四层配方 + 9 类交互技法(怎么做出来)
├── 3-references/  agent 的见识:本地风格档案库(可选) + 组件源 + 网站提取协议
├── 4-workflow/    agent 的干活流程 + 你的偏好档案(agent 自动维护)
├── 5-human/       你的部分:审美训练页 + 沟通速查 + 本手册
└── research/      调研底稿(全部结论的出处)
```

## 你只有 3 个必须出场的时刻

| 时刻 | 你做什么 | 花多久 |
|---|---|---|
| **1. 挑参考** | agent 给 3 个候选风格(带预览),你选 1 个 | 1 分钟 |
| **2. 点头 DESIGN.md** | agent 把方向写成一页设计指南针,你扫一遍确认 | 2 分钟 |
| **3. 每轮看效果** | agent 在浏览器里给你看真页面,你用反馈公式说话 | 随缘 |

其余一切(记录你的偏好、对照清单自检、查参考库、补状态、调参数)都是 agent 的事。
**这 3 个时刻是你品味进入系统的通道,外包不掉 —— 但都是选择题,不是简答题。**

## 日常 5 个场景,你说的话

### 场景 1:新项目开工
> "用 design-os 起步。我要做 ××(表达什么),给 ××(谁)看。参考这个(丢链接)/ 没参考,你从参考库挑 3 个给我。绝对不要 ××。"

agent 会:查参考 → 出 3 候选 → 你挑 → 写项目 DESIGN.md → 你确认 → 开做。

### 场景 2:日常改 UI
> 正常提需求就行,不用说任何设计术语。

agent 会:自动带着 1-judgment 标准 + 项目 DESIGN.md 干活,做完在浏览器截图自检,再给你看。

### 场景 3:你看到一个好看的网站
> "把这个站的设计语言提取一下,存进参考。"(丢链接)

agent 会:用 Playwright 打开 → 提取颜色/字体/间距/组件规则 → 存成一份 DESIGN.md 格式的参考,以后随时可用。

### 场景 4:你不满意
> 用反馈公式:**位置 + 问题(+ 方向)**。
> 例:"首屏主标题压不住场,层级太平 —— 再大再重,字距收紧。"
> 说不出术语就打开速查表对着说,或者干脆:"这里感觉廉价,你对照 judgment 清单自查一下。"

agent 会:修 + **自动把这条记进你的偏好档案**(你不用管)。

### 场景 5:验收
> "对照 DESIGN.md 和自检清单,列出这页最明显的 5 个问题再逐项修。"

这句是万能钥匙:不满意但说不清时,让 agent 自己找茬,通常能自己找出七八成。

## 怎么帮助 agent(4 做 1 别做)

**做:**
1. **挑参考时认真挑** —— 这是你品味注入的最大杠杆,一次选择顶一百句形容词
2. **反馈给"位置+问题"** —— 解法让 agent 提,你只负责指出哪里不对
3. **看到好东西随手丢链接** —— 一句"存进参考"就是在给系统喂弹药
4. **认可要说出来** —— "这个处理很好,记下来"会被自动收纳进偏好,比骂更能塑造系统

**别做:**
- 别用孤立的抽象形容词当反馈("高级一点""好看一点")—— 零信息量,agent 只能重新抽签。抽象词必须挂在参考上才有用:"像那个站那样的克制"。

## 偏好档案:全自动,你零维护

- 你每次**明确提出要求 / 纠错** → agent 记入 `4-workflow/preferences.md`
- 你每次**明确认可某个方案** → agent 把背后的设计决策收纳进去
- 同一条偏好跨项目出现 ≥2 次 → 升级为总偏好(所有项目默认遵守)
- 只在项目里出现过 → 留在该项目的 DESIGN.md,不污染别的项目
- 你永远不需要手动编辑它;想看系统学到了什么,直接打开那个文件或问 agent
